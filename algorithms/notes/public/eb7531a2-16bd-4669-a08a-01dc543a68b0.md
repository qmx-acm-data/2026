# 算法竞赛学习与训练建议

**先找出自己缺什么，再决定练什么，最后检查是否学会。**

本文结合 NOI 金牌选手的视频[《一个金牌选手的信竞攻略》](https://www.bilibili.com/video/BV1xSYxzDEPg/)整理，适用于 OI、ICPC/CCPC、Codeforces、AtCoder 等竞赛学习者。具体安排要随目标和基础调整。

## 一、想清楚为什么学竞赛

如果目标是升学或选拔，竞赛可能带来很高的回报，也可能投入多年却错过关键门槛。**提前了解规则、时间成本和退路。** <span style="color: #d32f2f;"><strong>投入多不代表一定成功。</strong></span>

如果目标是兴趣或能力，算法、推理和编程经验本身就是收获，不必只用奖牌衡量。

判断是否进步，要看最近一段时间学会了什么、能独立做出什么、代码是否更稳。一次比赛不能说明全部。

## 二、学习路线可以参考，不能照单全收

### 先知道有什么，再深入学习

竞赛知识有前后依赖，但**没有适合所有人的唯一学习顺序**。可以参考成熟路线入门，再根据自己的理解调整。

学一个算法，先弄清四件事：

- **有什么用？** 能解决什么问题，什么条件下能用？
- **先学什么？** 哪些知识是必需的？
- **有多重要？** 在目标比赛中是否常见？
- **学到哪一步？** 先了解用途，还是现在就掌握证明和代码？

> **先了解用途和大致思路，再补推导与实现。** 不必每个细节都懂了才往后看，但真正使用时要补齐必要知识。

### 优先补主干，边学边修正

最开始，主干知识都没学全，你就不要着急去熟悉比赛，因为做题的稳定性还没有，往往会有属于你这个阶段的题目你却不会，效率会比较低。

常用知识还不会时，先补这些缺口，别把大量时间花在冷门技术上。某个较难的方向如果学得顺，也可以继续，再回头查漏补缺。

算法基础有长期稳定的部分，题型、技巧和资料也会变化。**遇到新题、新理解，就修正旧笔记。**

## 三、选资料，也要选题

### 资料多，不代表都值得学

博客可能写错、漏步骤，也可能不适合自己的基础。优先找讲解清楚的资料；遇到疑点，再对照其他讲解、补推导或找反例。

**代码通过，不代表解释正确；名气大，也不代表每句话都对。** 最后要能用自己的话把方法讲清楚。

### 选题先看这次想练什么

| 想练什么 | 怎么选题 |
| --- | --- |
| **学新知识** | 知识点集中，有可靠题解，需要的基础能补上 |
| **练独立思考** | 能找到切入点，有些挑战，不依赖大量陌生知识 |
| **练代码** | 思路已清楚，但实现、边界或调试还不熟 |
| **练比赛** | 题型、难度和时限接近目标比赛 |

分数和标签只作参考。题太难，可能连有效练习都开始不了；题太熟，可能只是重复已有能力。

## 四、两种刷题方式搭配使用

### 独立做题：把已有能力练扎实

选与自己水平相近、有一定挑战的题，不看提示，尝试完成分析、证明、实现和调试。

重点是：**能否自己发现方法，并把题完整做对。**

卡住时，写下试过什么、为什么失败、还差哪一步。长时间没有新进展，可以看提示， **别把反复空想当成有效训练。**

### 借助题解：学习新的方法

前提是，把自己基础打好，不要过于好高骛远 **尤其是刚刚踏入一个阶段的学习。** 

选比自己独立水平适当难一些、但仍能理解的题，学习新算法、新思路和 Trick。**难度以能消化为准，不必强行跨几百分。**

具体的说，大概是比你现在水平的高一个难度的题目（洛谷能稳定做绿题，就去刷几道青题涨涨见识）。

看题解后，完成四步：

1. **补基础：** 把解法必需的知识补上。
2. **讲清楚：** 解释为什么想到这一步、为什么正确、复杂度是多少。
3. **自己写：** 离开原文整理推导，再独立写代码；需要学习优秀写法时，看懂后自行重写。
4. **换题试：** 在类似题中检查自己能否认出并使用这个方法。

> <span style="color: #d32f2f;"><strong>看懂题解、做出难题，不等于能在比赛中独立做出同难度的题。</strong></span>
>
> 区分记录：**独立完成、提示后完成、看题解后完成。**

### 缺什么，就多练什么

- **知识不会：** 多学讲解和典型例题。
- **知识会，但想不到：** 多做独立思考和类似题练习。
- **想对了，却写不对：** 多练实现与调试。
- **平时会，比赛发挥不出：** 检查选题、用时和失误。

两种做题方式都需要，比例随短板调整。

## 五、题解写清楚，Trick 留精华

### 题解要能回答“为什么”

记录四件事就够了：

- **卡在哪里，关键发现是什么？**
- **为什么这样做，凭什么正确？**
- **复杂度和代码要注意什么？**
- **下次遇到什么情况，可以用这个方法？**

刚学时写详细，熟练后删掉多余解释。**简单题可以只记一句关键结论，不必每题写长文。**

### Trick 要短，但条件不能丢

> **遇到什么条件 → 尝试什么方法 → 能解决什么问题。**

能推广就说明条件和理由；暂时总结不出规律，就先留代表题，等遇到更多例子再比较。

<span style="color: #d32f2f;"><strong>不要为了显得通用，把只在本题成立的结论推广到所有情况。</strong></span>

### 新的理解，写回原笔记

发现反例、漏掉条件或更好的解释，及时修改。笔记要越用越准、越用越简洁，不必越写越厚。

## 六、卡题能换任务，比赛要找原因

### 暂停前，留下下一步

可以保留三类任务：**待选题、待理解、待写代码。** 卡在一个环节时，先换一个能推进的任务。

> **暂停时写清：做到哪里、卡在哪里、下次先做什么。**

定期回头完成或放弃积压任务，别一直开新题、不收尾。

### 复盘要找到具体问题

知识没学完也可以参赛，用比赛了解题型、暴露问题。但常用知识还有缺口时，要留时间补课，不能指望只打比赛就自然学会。

| 比赛中出了什么问题 | 接下来练什么 |
| --- | --- |
| **相关知识不会** | 补知识、做典型题 |
| **知道方法，却没想到** | 找出题目中的提示，练类似题 |
| **推导有漏洞** | 补证明、找反例、重新讲一遍 |
| **思路对，代码错** | 练实现、边界检查和调试 |
| **选错题、耗时过长** | 调整做题顺序和换题时机，再用比赛检验 |

平时可以借题解学习；正式比赛和独立模拟时，遵守比赛规则。

### 休息后，要知道从哪里继续

高强度训练需要休息。留一个容易接上的任务，休息后更容易回来。

**看进步，不只看做了几题、涨了几分，也看少了哪些不会和失误。**

## 每次训练的五个问题

1. **今天主要练什么？**
2. **这道题适合独立做，还是借题解学？**
3. **我具体学会了什么？**
4. **不看原文，能讲清、写对吗？**
5. **下一次该补什么？**
