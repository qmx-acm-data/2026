# 贪心入门

> 用两道例题和一个反例，理解怎么选、为什么对、什么时候不对。

## 0. 贪心入门

### 0.1 贪心到底在做什么？

**每一步按照一个规则选择当前最合适的方案，并保证最终得到最优答案。**

先看具体问题，理解这里的“合适”由什么决定。

### 0.2 入门例题一：预算内买最多件商品

有 4 件商品，每件只能买一次，价格分别为：

```text
4、1、8、2
```

预算是 7，最多可以买几件？

#### 第一步：明确目标

目标是**件数最多**。每买一件，件数都增加 1，但消耗的钱不同。因此先考虑便宜的商品。

#### 第二步：确定选择规则

把价格升序排列，每次买当前最便宜、且买得起的一件：

```text
排序：1、2、4、8
```

| 当前选择 | 剩余预算 | 已买件数 |
| --- | ---: | ---: |
| 初始 | 7 | 0 |
| 买价格 1 的商品 | 6 | 1 |
| 买价格 2 的商品 | 4 | 2 |
| 买价格 4 的商品 | 0 | 3 |
| 下一件买不起，停止 | 0 | 3 |

这就是贪心：每一步直接确定选择，不再分别搜索“买这件”和“不买这件”的所有后续方案。

#### 第三步：为什么能保证最优？

**任意 k 件商品的总价，都不会低于最便宜的 k 件的总价。**

因此，优先买便宜商品时：

- 用最少的钱买到了当前这么多件；
- 如果连最便宜的 k+1 件都买不起，换成其他 k+1 件也买不起。

所以，停止时得到的件数就是最大值。这才是“便宜优先”正确的依据。

#### 第四步：转成代码

```cpp
int maxCount(vector<int> price, int money) {
    sort(price.begin(), price.end());
    int answer = 0;

    for (int p : price) {
        if (p > money) break;
        money -= p;
        ++answer;
    }
    return answer;
}
```

时间复杂度为 O(n log n)，主要来自排序。

**对应题单：§1.1 从最小 / 最大开始贪心。**

### 0.3 入门例题二：让数组严格递增

给定数组，只允许将元素加 1，求变成严格递增数组的最少操作数。

```text
原数组：1、1、3、2
```

这次位置不能打乱，直接从左到右处理：**当前数已经足够大就不动，否则增加到前一个数加 1。**

| 位置 | 原值 | 前一个调整后的值 | 当前应取的值 | 操作数 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 1 | — | 1 | 0 |
| 2 | 1 | 1 | 2 | 1 |
| 3 | 3 | 2 | 3 | 0 |
| 4 | 2 | 3 | 4 | 2 |

得到 `1、2、3、4`，共操作 3 次。

**为什么正确？** 每一位只增加到满足要求的最低值，既没有多花操作，也没有给下一位提出额外要求。如果当前位加得更多，只会让当前和后面的最低费用变高或不变。

**对应题单：§1.4 从最左 / 最右开始贪心。**

这两题代表两个常见方向：可以调整处理顺序时，从极值考虑；原位置有约束时，从左端或右端考虑。

### 0.4 为什么“每次选最好的”还不够？

有面额 `1、3、4`，每种硬币无限，凑出 6，求最少硬币数。

```text
每次选最大面额：4 + 1 + 1，共 3 枚。
真正的最优方案：3 + 3，共 2 枚。
```

选 4 看起来让剩余金额减得最多，却导致后面需要更多硬币。

因此，**局部最优是当前选择最好，全局最优是最终答案最好；二者之间需要证明，不能直接画等号。**

### 0.5 做贪心题，先回答三个问题

1. **怎么选？** 写出具体规则，例如价格升序、每次取最便宜的。
2. **为什么对？** 说明换成其他选择为何不会更好，而不是只演示样例。
3. **什么时候不对？** 检查目标和限制是否改变，例如商品价值不同、不能重排、区间带权等。

先把这三件事说明白，再研究证明术语和更复杂的数据结构。
