# 数组模拟变换相关公式

**简介：** 疑似在用数组模拟矩阵（二维）或序列（一维）旋转、对称等操作时，被下标对应关系逼疯而创造的 Trick。(qwq)

## 一、公式速查

**以下公式统一表示“旧元素搬到哪里”，代码写成 `b[新位置] = a[旧位置]`。**

### 一维：翻转与循环移位

设数组长度为 $n>0$，整条数组使用下标 `0..n-1`；旧下标为 $i$，新下标为 $i'$。循环移位的步数 $k$ 非负，先令 $k\gets k\bmod n$。

| 操作 | 新下标 $i'$ |
| --- | --- |
| 整条翻转（下标 `0..n-1`） | $n-1-i$ |
| 整条翻转（下标 `1..n`） | $n+1-i$ |
| 区间 $[l,r]$ 翻转 | $l+r-i$ |
| 关于位置 $c$ 对称 | $2c-i$ |
| 关于位置 $c$ 与 $c+1$ 之间对称 | $2c+1-i$ |
| 循环左移 $k$ 位（下标 `0..n-1`） | $(i-k+n)\bmod n$ |
| 循环右移 $k$ 位（下标 `0..n-1`） | $(i+k)\bmod n$ |

### 二维：使用区域内的位置

设操作区域左上角为 $(r_1,c_1)$，右下角为 $(r_2,c_2)$。设行数为 $H=r_2-r_1+1$，列数为 $W=c_2-c_1+1$。

对原格子 $(i,j)$，设区域内的位置为：

$$
u=i-r_1,\qquad v=j-c_1.
$$

于是 $u$ 在 `0..H-1`，$v$ 在 `0..W-1`。下表给出变换后的区域内位置 $(u',v')$。

| 操作 | 新位置 $(u',v')$ | 变换后大小 |
| --- | --- | --- |
| 上下翻转 | $(H-1-u,\ v)$ | $H\times W$ |
| 左右翻转 | $(u,\ W-1-v)$ | $H\times W$ |
| 旋转 180°（中心对称） | $(H-1-u,\ W-1-v)$ | $H\times W$ |
| 转置 | $(v,\ u)$ | $W\times H$ |
| 顺时针旋转 90° | $(v,\ H-1-u)$ | $W\times H$ |
| 逆时针旋转 90° | $(W-1-v,\ u)$ | $W\times H$ |
| 沿副对角线对称（限正方形） | $(H-1-v,\ H-1-u)$ | $H\times H$ |

目标区域也从 $(r_1,c_1)$ 开始时，**新位置加回起点**：

```cpp
b[r1 + u_prime][c1 + v_prime] = a[i][j];
```

> **注意：矩形转 90° 或转置后，行数和列数互换。** 目标数组必须能容纳新大小；若要求转后仍占据原来的整块区域，90° 旋转要求区域是正方形。

### 二维：常用的直接坐标公式

以下 $(i,j)$ 为旧坐标，右侧为新坐标。

| 操作与条件 | 新坐标 |
| --- | --- |
| 区域上下翻转 | $(r_1+r_2-i,\ j)$ |
| 区域左右翻转 | $(i,\ c_1+c_2-j)$ |
| 区域中心对称 | $(r_1+r_2-i,\ c_1+c_2-j)$ |
| 关于第 $R$ 行对称 | $(2R-i,\ j)$ |
| 关于第 $C$ 列对称 | $(i,\ 2C-j)$ |
| 绕中心 $(x,y)$ 顺时针 90° | $(x-y+j,\ x+y-i)$ |
| 绕中心 $(x,y)$ 逆时针 90° | $(x+y-j,\ y-x+i)$ |
| 关于中心 $(x,y)$ 对称 | $(2x-i,\ 2y-j)$ |

指定对称轴或中心时，变换结果未必落回原区域，需要检查目标范围。**拿不准直接坐标公式时，用上一张表先算区域内位置。**

## 二、一维翻转：两端位置配对

### 为什么是“两端之和减原下标”

```text
原数组：1 2 3 4 5
翻转后：5 4 3 2 1
```

区间 $[l,r]$ 内，$l$ 与 $r$ 互换，$l+1$ 与 $r-1$ 互换。每对下标之和都是 $l+r$，所以：

$$
\boxed{i'=l+r-i}.
$$

例如区间 $[3,6]$：

```text
3 ↔ 6
4 ↔ 5
```

**不需要找中心。** 奇数长度时中间元素不动；偶数长度时所有位置两两配对。

### 原地翻转

```cpp
for (int i = l, j = r; i < j; ++i, --j) {
    swap(a[i], a[j]);
}
```

时间复杂度 $O(r-l+1)$，额外空间 $O(1)$。

> **注意：每对位置只交换一次。** 如果遍历整个区间，逐个交换 `a[i]` 与 `a[l+r-i]`，每对会交换两次，最终回到原样。翻转两次本就应该还原，这也可用来验证代码。

### 对称位置为什么有时差 1

- 对称中心在位置 $c$ 上：$c$ 不动，配对下标之和为 $2c$。
- 对称中心在位置 $c$、$c+1$ 之间：两者互换，配对下标之和为 $2c+1$。

因此分别得到 $2c-i$ 和 $2c+1-i$。**把轴旁边的位置代进去，便能判断是否差了 1。**

## 三、一维循环移位：越过边界就绕回来

使用下标 `0..n-1`，先执行 `k %= n`：

```text
原数组：  1 2 3 4 5
左移 2：  3 4 5 1 2
右移 2：  4 5 1 2 3
```

左移时旧下标减 $k$，右移时加 $k$，再通过取模绕回数组范围：

```cpp
k %= n;

// 左移 k 位
for (int i = 0; i < n; ++i) {
    b[(i - k + n) % n] = a[i];
}

// 右移 k 位
for (int i = 0; i < n; ++i) {
    b[(i + k) % n] = a[i];
}
```

> <span style="color: #d32f2f;"><strong>左移的搬运公式减 k，右移加 k。</strong></span> C++ 的负数取模可能得到负数，所以先将 `k` 缩到 `0..n-1`，再用 `i-k+n` 计算。

### 多次移位：只记累计偏移

若操作始终是整条数组的循环移位，可以不实际搬运。设 `shift` 为累计向左移动的位数，初始为 `0`，始终保持在 `0..n-1`：

```cpp
// 每次先令 k %= n
// 若本次左移 k 位：
shift = (shift + k) % n;

// 若本次右移 k 位：
shift = (shift - k + n) % n;

// 当前下标 p 处的元素，来自原数组：
int value = a[(p + shift) % n];
```

**“旧元素搬到哪里”和“当前位置从哪里取值”方向相反。** 左移后的下标 $p$，装的是原来下标 $p+\text{shift}$ 的元素，因此查询公式用加号。

每次操作 $O(1)$，最后遍历输出。设操作数为 $m$，总时间复杂度为 $O(n+m)$。

## 四、二维对称：行列分别配对

矩阵中，**行号向下增大，列号向右增大**。

### 上下翻转：只改行

第一行和最后一行配对，列不变：

```cpp
b[r1 + r2 - i][j] = a[i][j];
```

- 对称轴在第 $R$ 行上：新行是 $2R-i$。
- 对称轴在第 $R$、$R+1$ 行之间：新行是 $2R+1-i$。

### 左右翻转：只改列

第一列和最后一列配对，行不变：

```cpp
b[i][c1 + c2 - j] = a[i][j];
```

- 对称轴在第 $C$ 列上：新列是 $2C-j$。
- 对称轴在第 $C$、$C+1$ 列之间：新列是 $2C+1-j$。

### 中心对称：行列同时配对

上下翻转再左右翻转，等于旋转 180°：

```cpp
b[r1 + r2 - i][c1 + c2 - j] = a[i][j];
```

> **偶数边长只有一个几何中心，它在中间四个格子的交点上。** 不需要选某个格子作中心；用两端配对，四个中间格子会自然交换位置。

二维翻转也可以原地交换：上下翻转只处理上半部分，左右翻转只处理每行的左半部分，保证每对只交换一次。

## 五、旋转 90°：转置后再翻转

### 先换成区域内的位置

对格子 $(i,j)$，减去区域左上角：

$$
u=i-r_1,\qquad v=j-c_1.
$$

**在这个从 $(0,0)$ 开始的小矩阵里做变换，最后加回起点。** 奇数、偶数边长都一样，不用算中心。

### 转置：交换行列

$$
(u,v)\longrightarrow(v,u).
$$

```text
原矩阵：       转置后：
1 2 3          1 4
4 5 6          2 5
               3 6
```

转置后，$H\times W$ 变成 $W\times H$。对正方形，转置就是沿主对角线对称。

### 顺时针：先转置，再左右翻转

```text
原矩阵：       转置后：      左右翻转后：
1 2            1 3           3 1
3 4            2 4           4 2
```

转置后位置为 $(v,u)$，新矩阵有 $H$ 列。左右翻转后，新列为 $H-1-u$：

$$
\boxed{(u,v)\longrightarrow(v,\ H-1-u)}.
$$

### 逆时针：先转置，再上下翻转

转置后新矩阵有 $W$ 行。上下翻转后，新行为 $W-1-v$：

$$
\boxed{(u,v)\longrightarrow(W-1-v,\ u)}.
$$

> **注意方向和顺序：先转置，顺时针翻左右，逆时针翻上下。** 检查时，左上角顺时针应到右上角，逆时针应到左下角。代码直接用合成后的公式，无须实际做两次变换。

### 副对角线对称

对边长为 $L$ 的正方形，先交换行列，再同时翻转：

$$
(u,v)\longrightarrow(L-1-v,\ L-1-u).
$$

主对角线是左上到右下，副对角线是右上到左下。**对角线对称和旋转不同，不能只看公式相近就混用。**

## 六、子方阵旋转模板

设操作区域为 $[r_1,r_2]\times[c_1,c_2]$，要求它是正方形，边长为 $L=r_2-r_1+1$。`a` 为原数组，`b` 为临时数组。

```cpp
// 前提：区域为正方形，且全部下标在数组范围内
// z = 0：顺时针；z = 1：逆时针
void rotateSquare(int r1, int c1, int r2, int c2, int z) {
    int L = r2 - r1 + 1;

    for (int i = r1; i <= r2; ++i) {
        for (int j = c1; j <= c2; ++j) {
            int u = i - r1;
            int v = j - c1;
            int ni, nj;

            if (z == 0) {
                ni = r1 + v;
                nj = c1 + L - 1 - u;
            } else {
                ni = r1 + L - 1 - v;
                nj = c1 + u;
            }

            b[ni][nj] = a[i][j];
        }
    }

    for (int i = r1; i <= r2; ++i) {
        for (int j = c1; j <= c2; ++j) {
            a[i][j] = b[i][j];
        }
    }
}
```

### 为什么先写 b，再拷回 a

直接写 `a[新位置] = a[旧位置]`，可能覆盖还没有搬走的旧值。**先完成全部搬运，再拷回，才能保留本轮所需的原数据。**

正方形的 90° 旋转会恰好写满原区域，因此 `b` 不用提前清空；如果公式写错，清空 `b` 也无法解决问题。

一次操作时间复杂度为 $O(L^2)$。只为这块区域开临时数组时，额外空间为 $O(L^2)$；若开整张临时矩阵，空间按整张矩阵大小计算。

### 题目给定中心时，先转为边界

设中心为 $(x,y)$、半径为 $r$：

```cpp
int r1 = x - r, r2 = x + r;
int c1 = y - r, c2 = y + r;
rotateSquare(r1, c1, r2, c2, z);
```

展开后，顺时针公式为：

```cpp
b[x - y + j][x + y - i] = a[i][j];
```

> <span style="color: #d32f2f;"><strong>不能简写成 `b[j][2*x-i]`。</strong></span> 这会漏掉中心列坐标，只在 $x=y$ 时碰巧正确。自测至少加入一组 $x\ne y$ 的查询。

### 测试哪些情况

- **偶数边长：** 如 $2\times2$、$4\times4$，检查是否误用了整数中心。
- **起点行列不同：** 检查是否漏掉区域起点。
- **矩形转置、旋转：** 检查目标长宽是否交换。
- **重复操作：** 90° 旋转四次后应还原，顺时针再逆时针也应还原。

## 七、空间与多次操作优化

### 原位旋转

90° 旋转可以将四个位置循环交换，额外空间为 $O(1)$，但下标更易写错。先掌握临时数组版本，需要省内存时再使用原位版本。

矩阵存储为 $O(n^2)$。**边长开大十倍，内存增大一百倍**，数组应按题目范围分配。

### 多次整表操作可以合并

- 整条数组只做循环移位：累计偏移。
- 同一张正方形只做 90° 旋转：累计旋转次数，对 `4` 取余。
- 整张方阵混合旋转、翻转：记录整体方向状态，最后生成结果。

**不同子区域上的操作，不能直接合成一个整表方向状态。**

## 一句话记忆

> **翻转看两端，旋转先换行列；先算区域内的位置，再加回起点。**
